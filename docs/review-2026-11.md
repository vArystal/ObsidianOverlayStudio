# Review and hardening, November 2026

Target: `vArystal/ObsidianOverlayStudio`, backend items P0–P2 plus the maintainability groundwork from P3.
Everything below was verified locally with the commands at the end of this file. Live Kick behavior was not
exercised: no production Kick credentials or public webhook endpoint are available in this environment.

## Fixed

| Item | Defect | Fix | Regression test |
| --- | --- | --- | --- |
| 1 | Concurrent `flush()` calls shared one temp path and the second `rename` failed with `ENOENT` (19 of 20 concurrent writes in the reproduction) | All persistence runs through a single promise chain; each write uses a unique temp name; the snapshot is serialized at write time so a slow write cannot resurrect stale state | `server/concurrency.test.mjs` "item 1": 50 mixed concurrent mutations, zero rejections, file re-read parses and holds all 50 |
| 2 | `markProcessed` ran before delivery, so a failed `updateConnection` lost the event permanently | The claim is recorded before delivery and released if delivery throws, so Kick's retry is processed | "item 2": injected `updateConnection` failure, retry is not a duplicate, publishes exactly once |
| 3 | `isProcessed` then `markProcessed` is not atomic; identical deliveries could both publish | `store.claimMessage()` checks and records inside the write queue in one turn | "item 3": 20 identical deliveries publish once, 19 report duplicate |
| 4 | `sessionFollowerCount + 1` on a value read before an `await` | `store.incrementSessionFollowers()` increments inside the queue | "item 4": 25 concurrent follows produce 25 |
| 5 | Reconnecting the same Kick account left the old connection active, and `findByBroadcasterId` returned it, so webhooks missed the new connection and its OBS URLs | `saveConnection` reuses the existing record (same `id` and `runtimeKey`, so OBS sources keep working, fresh management token, refreshed tokens/scopes) and retires any other record for that account; `findByBroadcasterId` prefers the most recently updated active connection | "item 5": one active connection, same runtime key, publication still resolves |
| 6 | Concurrent `validAccessToken` calls refreshed the same rotating refresh token, invalidating each other | `createTokenRefresher()` shares one in-flight refresh per connection and re-reads the token inside it | "item 6": 10 concurrent calls, one `client.refresh`, identical tokens, map cleared |
| 7 | A missing encryption key silently fell back to a hardcoded string | `createApp` throws in production when the key is absent or shorter than 32 characters; development keeps the fallback with a loud warning | `server/hardening.test.mjs` "item 7" |
| 8 | A disconnected integration produced a 30-second reconnect loop forever | On a closed stream the provider keeps the fast retry but probes `/state`; a positive `connected: false` cancels it and sets the terminal `disconnected` state. `loadState` now honours `connected: false` instead of mapping it back to `connecting` | `LiveDataProvider.reconnect.test.tsx`: 409 case stops after one stream over two minutes; an unreachable probe still retries |
| 9 | Deleting an overlay left its backend publication and runtime key alive | New `DELETE /api/overlays/:overlayId/publication` (management bearer auth, idempotent) plus `deletePublication()` called from the library delete flow, which surfaces a failure instead of hiding it | Route covered by the status table tests; see limits below |

## Deferred, with reasons

- **Item 13 extraction.** The shared-module extraction is explicitly gated on P0–P2 being merged, and it is a
  refactor with real regression risk in a runtime I cannot exercise here (the Cloudflare worker needs a
  deployed environment). The decision note names the target and the module boundary so the work can start
  from a written plan rather than a blank page.
- **`worker/index.mjs` parity.** The same defects almost certainly exist there. They are not patched in this
  pass because the worker cannot be tested in this environment, and an untested concurrency change to a live
  webhook path is worse than a documented gap. `docs/backend-consolidation.md` lists the exact functions.
- **Item 9 end-to-end.** The route and the client call are implemented and unit-tested, but "after delete,
  `GET /api/runtime/<old key>/state` returns 404" needs a running backend plus a real publication; the store
  test proves the publication is removed, which is the mechanism the route relies on.
- **Editor save cost, canvas nudging and probes.** Not changed in this pass. Reading `saveOverlay` confirms it
  rewrites the whole overlay list on every save, which is acceptable at local-first scale (tens of overlays,
  hundreds of KB) but is the reason a SQLite/IndexedDB store is the right long-term move.

## Risks I could not verify

- **Live Kick retry behavior.** The status table follows Kick's documented retry-on-5xx contract. Whether Kick
  also retries on `429` or honors `Retry-After` is unverified without credentials.
- **Refresh-token rotation semantics.** The de-duplication assumes Kick invalidates the previous refresh token
  on use. If it does not, the fix is still safe, just less necessary.
- **`worker/.wrangler` history.** The files were untracked going forward. A scan of tracked content for
  client-secret and refresh-token shapes found nothing, and the worker local state holds encrypted tokens under
  a development key, but the history still contains those blobs. Purging them needs `git filter-repo` and a
  force-push, which is not done without the owner's explicit approval.
- **Real webhook delivery.** As of the last checkpoint no organic Kick delivery had ever arrived, so every
  delivery test here is synthetic (signed with a locally generated RSA key).

## Note on the tuning probe from October

The previous session recorded a "tuning resets on reload" bug. It was a probe artifact: `addInitScript`
re-seeds `localStorage` on *every* navigation, so the reload wrote the original crimson overlay back before
the app read it. The probe now seeds only when the key is absent, and the reload keeps the chosen values.
